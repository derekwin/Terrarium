# 设计决策记录

历次设计讨论的收敛结论。每条记录决策内容、理由与当前实现状态。

## D1. 威胁模型边界：L2 是行为治理，不是对抗性隔离

**决策**：L2（confine/sandlock）不承诺对抗恶意代码。它的职责是行为治理
——默认拒绝、显式授权、审计、资源限制。L2 逃逸的后果被限制在**租户自身**
（同 VM 其他 sandbox 的 workdir 数据），不跨租户。对抗恶意代码的场景
（不可信代码执行）必须走 VM 级隔离（每任务独立 VM，或受信任务共享）。

**理由**：VM（KVM）是唯一对抗性边界；Landlock/seccomp 类进程级隔离以
"合法但越权"的 agent 为假设，对抗逃逸成本高且与密度目标冲突。

**实现状态**：能力面已按此收敛（无 Execute/Inbound/Device/带宽等悬空
能力）；L2 后端 confine（默认）+ sandlock（alternative）。

## D2. 网络终局：per-tenant 网段 + 宿主转发

**决策**：从共享桥（terra0 + ebtables 隔离，过渡方案）演进到每租户独立
网段 + 宿主转发（NAT + 策略路由）；`Bridge` 直通作为显式逃生口（P3，
对外暴露场景）。

**理由**：共享桥扩展性差（VM 间流量过宿主桥、规则随租户增长）；
per-tenant 网段隔离语义清晰，为多机（P3）铺路。

**实现状态**：当前共享桥 + ebtables 租户 L2 隔离（已验证）；per-tenant
网段为规划（P2/P3）。

## D3. 层镜像分发（多机前置基建）

**决策**：层（erofs）是天然分发单元——需要定义层镜像的 registry 与
分发协议（类 OCI），多机编排前补上。

**理由**：当前层构建是单机流程（`terra tool create` → 本地
`layers/` 目录）；多机要么复制文件要么重建，不可扩展。

**实现状态**：单机层构建/挂载已落地；分发协议未实现（P3 前置）。

## D4. 部署形态：root daemon + systemd；审计可运维

**决策**：daemon 以 root 运行（需要 NAT/挂载/ebtables），生产以
systemd 服务托管（服务单元、日志接管）；审计文件（`$TERRA_HOME/audit/
audit.jsonl`）对启动用户可读（fchown 到 sudo 原用户），运维/开发无需
root 即可查阅。

**理由**：root 是功能所需（网络/挂载），systemd 是标准托管形态；审计是
治理核心，运维必须能读（0600 root 会阻断排查）。

**实现状态**：audit JSONL 落盘 + fchown 到原用户（D4 落地）；systemd
单元为后续包装。

## D5. 策略可编程（平台级方向）

**决策**：策略从静态 JSON 演进为"策略即代码"——SDK 构造器、可继承、
可热更新，支持平台级策略管理（配额、审计、多租户模板）。

**理由**：任务级策略（每个 agent 任务自己声明）是起点；平台级策略
（管理员统一治理）是 SaaS/多租户的分水岭（对应 R10）。

**实现状态**：SandboxPolicy 类型化 + 继承 + 校验已落地；策略管理 API
（CRUD/热更新）未实现。

## D6. Agent 生态接口（MCP 工具面扩展）

**决策**：MCP 工具面从管理面（当前 18 个）扩展 agent 运行面：会话恢复
（长任务断线重连）、文件上传/下载、密钥与环境注入、多 agent 并发
隔离。

**理由**：MCP 是 agent 的直接入口；agent 需要的不只是 exec——长任务
可靠性、数据进出、凭据管理、任务编排是产品化最直接的界面。

**实现状态**：MCP 会话式 exec（默认 confine 约束）+ 后台会话 + 审计
查询已落地；会话恢复、文件传输、密钥注入未实现。
