**T4 root cause found & fixed**: `CONFIG_VIRTIO_MEM=y` alone was silently dropped by
`olddefconfig` — it `depends on MEMORY_HOTREMOVE + CONTIG_ALLOC + EXCLUSIVE_SYSTEM_RAM`
(drivers/virtio/Kconfig). Added the three deps to `images/kernel/config-minimal`,
rebuilt kernel, and memory resize became real: CH `vm.info` shows
`hotplugged_size=536870912` and engine info reports `memory_mb: 1024`.
(First round's "guest-side limitation" note was actually this missing-dependency bug.)

## P8: CH API shape (integration tests) — ✅ PASS (3/3 against real CH v53)

Two test-infra bugs found & fixed while running:

1. **Silent skip**: `env_ready()` used relative `target/guest/vmlinux.bin`, but
   `cargo test` sets CWD to the package dir — all KVM tests skipped silently.
   Paths now resolve via `CARGO_MANIFEST_DIR` (`../../../target/guest/`).
2. **Forever hang** (round-1 "Hung" root cause): tests called
   `vm_shutdown` then bare `child.wait()` — but the minimal busybox guest has
   no acpid and ignores the ACPI power button, so CH never exits. New
   `stop_ch()` helper: API shutdown → 5s `try_wait` grace → force kill.

Result: `3 passed; 0 failed` in 15.54s — `vm.info`/`vm.resize`/`vm.shutdown`
verified against real CH v53, memory resize 512M→1G→768M with virtio-mem.

## Notes / test-harness errata (not product bugs)

- `pgrep -f` matches the invoking bash wrapper — process-leak checks in this
  report use `ps -eo comm` exact matching instead.
- Daemon PID capture: `$!` in a compound command can point at the wrapper
  shell; signal tests must resolve the engine PID via `pgrep -f '^target/release/engine daemon'`.
- **CH v53 `vm.shutdown` semantics** (verified by A/B experiment): it is a
  VMM-level stop, not an ACPI power button — the VM halts and state returns
  to `Created` regardless of guest cooperation, and **the CH process stays
  alive** in API mode waiting for new config. Engine code must not
  `child.wait()` after `vm.shutdown` (use `stop_ch`-style grace+kill).
  The real ACPI path (`vm.power-button`) does need guest cooperation —
  the guest rootfs now ships busybox `acpid` + `/etc/acpi/PWRF/00000080`
  (→ `poweroff -f`), and the kernel has `CONFIG_INPUT_EVDEV=y` so button
  events reach userspace.
