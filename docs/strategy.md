# Terrarium 落地战略

> 定位一句话：**真 VM 隔离 × 容器级密度** —— agent 沙箱基础设施。
> 目标场景收敛为三个：RL 训练、Agent 生产执行、Agent 写代码的 CI。
> 评测/安全研究/插件市场/多租户 SaaS 不设为主要战场（共用同一引擎，能力自然覆盖）。

## 为什么是这个定位

现有沙箱方案在两个极端之间：容器（Docker/gVisor）密度高但隔离弱；微虚拟机
（Firecracker/Cloud Hypervisor）隔离硬但每实例开销大。Terrarium 用
**KVM 租户隔离 + 会话内 sandlock** 的两层模型，把每 VM 成本压到 ~56-65MB、
冷启动 ~850ms、暖池认领 ~620ms——落在中间带：真 VM 隔离，容器级密度。

当前实测数据（2026-08-03，12 租户采样）：

| 指标 | 数值 |
|---|---|
| 冷启动 p50 | ~850 ms |
| 租户内追加 sandbox p50 | ~18 ms |
| 每 VM 内存（RSS/Pss）| ~64 / ~52 MB |
| 层共享占比（ubuntu 99MB 层）| 20.9%（164MB @ 12 VM）|
| exec p50 | ~5 ms |
| 并发吞吐（16 并发）| ~330-344 execs/s |

## 目标场景画像

### 1. RL 训练 —— 大规模并行环境

训练 agent（代码生成、工具使用）需要成百上千个隔离执行单元，每个 episode
要**快速重置**，环境间绝不能相互干扰，成本决定训练规模。

- Terrarium 已有：高密度（56MB/VM）、共享层（层只存一份）、暖池亚秒启动、
  `VmAdapter`/`SandboxAdapter` 抽象。
- 差距：
  - **快照快速重置**——episode 结束不是冷重启（~850ms），而是快照恢复
    （目标 <100ms）；这是规模化训练的关键，也是之前"快照容错"讨论的正确
    姿势：**做快速重置，不做崩溃恢复**。
  - **批量编排**——一次拉起/回收数百环境的批量 API，而非逐个
    `sandbox_create`。
  - CPU/内存配额按训练任务声明（sandbox limits 已有雏形，需按 episode
    声明并强制）。

### 2. Agent 生产执行 —— 安全、可审计、可治理

生产 agent 执行不可信代码，安全边界、行为审计、策略治理是准入前提。

- Terrarium 已有：KVM 租户隔离、sandlock 会话隔离、能力化
  `SandboxPolicy`（默认拒绝）、结构化审计事件（exec/deny/resource）、
  MCP 接入。
- 差距：
  - **审计产品化**——tracing 文本 → 可查询审计 API + 事件导出，让平台
    能回答"这个 agent 干了什么、被拒了什么"。
  - **策略/配额管理**——每租户配额、任务级策略模板、网络出口加固
    （`net_allow` 已存在但运行时验证未闭环）。
  - **长会话持久化**——agent 任务常常是小时级，需稳定的长连接与会话恢复。

### 3. Agent 写代码的 CI —— 隔离的代码验证管道

agent 产出代码后，需要在隔离环境里跑测试/构建再决定合入。本质是
"CI runner + 安全边界"。

- Terrarium 已有：层化环境（工具层构建）、快启动、exec/文件接口。
- 差距：
  - 与 CI 系统的集成形态（运行器协议、环境缓存）。
  - 测试失败/agent 恶意代码的失败隔离与审计（复用场景 2 的审计面）。

## 阶段路线图

### P1 —— 训练/评测基础设施（最高优先）

1. **快照快速重置**：沙箱级 checkpoint → 恢复，目标重置 <100ms；
   定位是"快速回收环境"，**不是崩溃容错**（后者维持不做）。
2. **批量编排**：batch 生命周期 API（批量 create/recycle/collect）+ 密度
   报表；单节点即可服务数百环境。
3. **RL 协议接入**：以 MCP 为统一入口，提供环境重置、任务注入、
   结果采集的原语。

### P2 —— 生产执行治理

4. **审计产品化**：结构化审计事件 → 查询 API（✅ `audit_list` 命令 +
   有界环形缓冲 + SDK/CLI/MCP 面，2026-08-04）+ 导出（JSONL/Webhook，
   后续）。
5. **策略/配额管理**：租户配额、任务策略模板、网络出口加固。
6. **安全验证闭环**：逃逸/加固测试；在真实 KVM 宿主上完成 sandlock deny
   通道与 fsgrant 的运行时验证（当前仅编译级）。

### P3 —— 规模化

7. **多主机编排**：单节点 → 集群（数千环境）。`VmAdapter`/`SandboxAdapter`
   抽象已为异构后端留口，此阶段重点是调度与跨节点状态。

## 明确不做

- 池自动扩缩容（固定池 + 手动 `grow/scale` 已够用，2026-08-03 定）。
- 快照崩溃容错（agent 可重跑，重启优于恢复；快速重置是另一回事）。
- 评测/安全研究/插件市场/SaaS 作为**独立产品线**（能力随主场景自然覆盖）。
