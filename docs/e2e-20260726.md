**Note**: Daemon must be started directly (not inside tmux). When started inside tmux, spawned CH processes cannot access `/dev/kvm` (Permission denied — tmux session environment difference). ### T2 — VM with disk

**Result**: ✅ PASS (with workaround)

CH v53 **rejects all qcow2 backing chains** (error: `MaxNestingDepthExceeded`). This is a CH v53 limitation — any qcow2 with a backing file (including `qemu-img create -b`) is rejected regardless of nesting depth. Standalone qcow2 (no backing) works fine.

**Workaround**: Created standalone qcow2 disk and passed via `disks` field (raw JSON):
```
disks: ["/var/tmp/t2-disk.qcow2"]
```
→ VM boots, single `--disk` in CH args, `info` shows state=Running ✓

**Impact**: Overlay-based disk strategy (`base_disk → overlay.qcow2`) is incompatible with CH v53. Either: (a) use CH version that supports backing chains, (b) switch to raw format, or (c) copy-on-create instead of overlay.

### Timeout (sleep 300)

**Result**: ✅ PASS (with process group note)

```
Response after 60.0s: "command timed out after 60s"
```

Timeout correctly triggers at 60s ✓. However, when the command is `sh -c 'sleep 300'`, the kill targets only the direct child (`sh`), and the grandchild (`sleep 300`) is orphaned (PPID=1). This is a known process group cleanup gap — kill should target the process group, not just the PID.

### New Issues Discovered

1. **CH v53 rejects qcow2 backing chains** (MaxNestingDepthExceeded) — overlay strategy incompatible. Requires CH version upgrade or alternative disk strategy.

2. **tmux spawn prevents /dev/kvm access** — daemon started inside tmux cannot spawn CH processes that access KVM. Workaround: start daemon outside tmux.

3. **guest-proxy process group cleanup** — kill targets only direct child PID, not process group. Grandchild processes (e.g., `sleep` inside `sh -c`) become orphaned.

### Pre-existing Issues Confirmed

- SIGTERM not handled (CH processes leak) — §6 known
- Global Mutex serializes VM operations — §6 known
- Memory resize needs virtio-mem guest driver — expected
- Dual CLI (`crates/cli` vs `engine/src/cli.rs`) — §6 known
