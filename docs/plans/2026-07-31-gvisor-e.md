# E 阶段:gVisor 后端实证(SandboxAdapter 可替换性)

> **目标**:接入第二个异构 `SandboxAdapter` 实现(gVisor/runsc)——host 侧独立
> 沙箱(用户态内核),不依赖 VM 内机制——证明边界契约完备:引擎零改动,
> 后端可插。这是整套学术设计的最终实证。

---

## 1. 设计(契约承载异构)

**两个后端的异构性**(正是实证价值):

| | GuestSandlockAdapter(默认) | GvisorAdapter(新) |
|---|---|---|
| 隔离机制 | guest 侧 sandlock(Landlock/seccomp) | host 侧 gVisor(用户态内核) |
| 依赖 | 经 `VmHandle::exec`(需 VM) | **不依赖 VM**(host 独立沙箱) |
| 隔离强度 | 进程约束 | 独立内核(更强) |
| 资源 | guest 资源(VM 配额内) | host 进程资源 |

**契约同一**:两者都是 `SandboxAdapter::create(vm, spec) → SandboxHandle`——
gVisor 后端**忽略 vm 参数**(它不需要 VM),这正是"契约完备"的证明:
trait 不假设后端需要 VM。

## 2. 实现:gVisor 后端 crate

`crates/adapter/gvisor`(新 crate,lib 名 `adapter-gvisor`):

```
GvisorAdapter { runsc: PathBuf, root: PathBuf }   // runsc 二进制 + 状态目录
  create(vm, spec):                                // 忽略 vm
    - 建沙箱: bundle 目录 + config.json(OCI)
    - rootfs = spec 提供的层目录(只读)或 host 目录; /tmp tmpfs; workdir rw
    - runsc run -root=<state> -bundle=<bundle> <id>
    - 返回 GvisorHandle
  exec(cmd):
    - runsc exec -root=<state> --cwd=<workdir> <id> <args...>
    - 捕获 stdout/stderr/exit_code
  setup/destroy: runsc delete <id>
```

**policy 映射**(最小):
- 默认隔离:rootfs 只读 + /tmp tmpfs + workdir 可写(对齐 sandlock 默认语义)
- File capabilities → 额外 rw 挂载(host 目录)
- Network/Device/Execute → 诚实报错(后端不支持,gVisor 网络后续)
- limits → runsc 资源限制(--cpu-num/--memory-limit)

**单测**:runsc 命令构造(不真跑)、bundle config.json 生成、policy 映射。

## 3. 接入与实证

**engine 零改动**:通过现有 `VmManager::with_sandbox_adapter` 注入(已有 DI)。

**实证分两步**:
1. **独立实证**(不依赖 daemon):直接用 `GvisorAdapter` + runsc——
   创建沙箱 → exec 命令(验证输出)→ 验证隔离(沙箱内写 host 只读路径被拒)→ destroy
   ——证明后端实现真实工作
2. **引擎实证**:engine 测试注入 `GvisorAdapter`,sandbox 走 gVisor 后端
   ——证明契约面(engine 零改动,后端可换)

**环境**:runsc 已下载(~/.local/bin/runsc);需 root 运行(runsc 建沙箱需权限)——daemon 是 root,可用。

## 4. 验收(契约完备判据)

1. 两个异构后端(guest sandlock 经 VM / gVisor 独立)走同一 `SandboxAdapter` 契约
2. engine 核心零改动(grep 证实:engine 不引用 gvisor crate)
3. gVisor 后端真实运行:create/exec/destroy + 隔离验证
4. 不足处按契约补接口(若 gVisor 需要契约没有的能力 → 契约扩展;期望是无)

## 5. 明确不做

- gVisor 完整 OCI 支持(最小 bundle 即可——实证目的是契约,非 gVisor 产品化)
- Network/Device capability 的 gVisor 实现(诚实报错)
- 生产化接入(daemon 配置选后端)——实证后如需,再配置化
